# api — Developer and Agent Guide

The new backend (replatform, `docs/decisions.md` D39–D53): a Django app in one Docker image. It runs locally in `docker compose` and in production on Cloud Run (`asia-southeast1`), with PostgreSQL (local container, Neon in the cloud). **Phase 2**: the data model, the admin site and the sheet import exist; the only endpoint is `GET /api/health` (the REST API is Phase 3). The live backend is still `apps-script/` until the switch-over.

Read first: root `CLAUDE.md`, `README.md` (Local development) and `docs/decisions.md` D39–D53.

## 2. Data model (`foodies/models.py`)

Mapped from the sheet (`apps-script/src/Config.js`), English names (D51). UUID primary keys keep the sheet's App ID and Dish ID. Tables live in the `public` schema with plain names set by `db_table` (`places`, `dishes`, `place_ratings`, `place_labels`, `photos`, `labels`, `people`, `master_options`, `places_usage`, `audit_log`, `collections`, `collection_places`); Django's own tables keep their `auth_*` / `django_*` names. A new model gets a `db_table` too.

| Model | Holds | Sheet source | Notes |
|---|---|---|---|
| `Person` | The two users: name, Google email (Phase 3), `position` 1 or 2 | Script Property `PEOPLE` | `position` = order of the Rating / Review columns |
| `MasterOption` | `kind` (rating / type / genre / category), `value`, `rank` | "Master" | Unique per kind; for ratings, higher rank = better |
| `Label` | Tag name | "Labels" cell | Unique ignoring case (`cleanLabels_` rule) |
| `Place` | All place fields, `labels` (many-to-many), Google fields, `version` | "Food List" | `id` = App ID; `version` for the edit conflict check (D24). UniqueName and Hyperlink are derived, not stored |
| `PlaceRating` | `place`, `person`, `score` (a Master rating), `review` | Rating / Review (name) columns | One per person per place |
| `Dish` | `place`, name, price, liked (''/Yes/No), best, note | "Dishes" | `id` = Dish ID; deleted with its place |
| `Photo` | `place` **or** `dish`, `position` (0 = cover), `key` / `thumb_key` (bucket, Phase 3), `drive_id` | "Photos" cells | A check constraint requires exactly one owner |
| `PlacesUsage` | `period` ("2026-11-22" or "2026-11"), `count` | Script Property `USAGE` | Places spend counter (Phase 3) |
| `AuditLog` | `at`, `person`, `action`, `entity`, `entity_id`, `changes` (JSON) | — | Every write; read-only in the admin |
| `Collection`, `CollectionPlace` | Named list of places (name, note, `version`); entries with `added_at` / `added_by` | — | D49; a place appears once per collection |

Text limits are generous in the database; the API enforces the sheet's limits (`cleanValue_`, `cleanDish_`) in Phase 3.

## 3. Endpoints

| Method + path | View | Response |
|---|---|---|
| `GET /api/health` | `foodies.views.health` | `{"ok": true}` after a `SELECT 1`; `503 {"ok": false, "error": "Database unavailable"}` when the database is unreachable |
| `/api/admin/` | Django admin | Login with a Django superuser. Admin CSS is served locally by runserver; on Cloud Run it is not served yet (D53) |

## 4. Settings (environment variables)

| Variable | Required | Local (`docker-compose.yml`) | Cloud Run |
|---|---|---|---|
| `DATABASE_URL` | yes | the `db` container | Secret Manager `DATABASE_URL` (Neon pooled string, `sslmode=require`) |
| `DJANGO_SECRET_KEY` | yes | `local-dev-only` | Secret Manager `DJANGO_SECRET_KEY` |
| `DJANGO_DEBUG` | no | `1` | unset (off) |
| `DJANGO_ALLOWED_HOSTS` | no | `*` | `*` (default) |
| `PORT` | no | — (runserver on 8000) | set by Cloud Run; image default 8080 |

`DISABLE_SERVER_SIDE_CURSORS` is on because Neon's pooler (PgBouncer, transaction mode) cannot keep server-side cursors. Static URL `/api/static/`. Time zone `Asia/Jakarta`: sheet times without a zone are read as Jakarta time. Logs go to stdout (Cloud Logging on Cloud Run). Never log tokens, keys or a user's location.

## 5. Commands (all inside Docker, from the repo root)

| Task | Command |
|---|---|
| Run API + database + web | `docker compose up` |
| Tests | `docker compose run --rm api python manage.py test` |
| After changing `models.py` | `docker compose run --rm api python manage.py makemigrations` (commit the new file), then `… migrate` |
| Check models and migrations match | `docker compose run --rm api python manage.py makemigrations --check --dry-run` |
| Admin user (local) | `docker compose run --rm api python manage.py createsuperuser` |
| Sheet import | `docker compose run --rm api python manage.py import_sheet --people "Name1,Name2" --places food-list.csv [--dishes dishes.csv] [--master master.csv] [--dry-run]` |
| Rebuild after changing `requirements.txt` | `docker compose build api` |

**`import_sheet`** reads CSV exports (File → Download → CSV, one per tab) placed in `api/` (mounted at `/app`). Never commit them (`.gitignore` ignores every `*.csv`). It:
- Accepts the English headers and the old Indonesian ones (`OLD_HEADERS` in `apps-script/src/Setup.js`).
- Matches places by App ID and dishes by Dish ID, so a re-run updates rows.
- Skips, with a warning, rows without a valid App ID (opening the live app once assigns them) and dishes whose place was skipped.
- Records photos by Drive file ID only; copying them to the bucket is Phase 3.
- Reads only ISO dates for Added At (others keep the import time). Which format a real export uses is **Unverified**.
- Runs in one transaction; `--dry-run` rolls back. `--people` gives the two names used in the `Rating (<name>)` headers, in sheet order; names stay out of the repo.

## 6. Conventions

- Settings only from environment variables; no secret, ID or URL in code (root `CLAUDE.md` § 5).
- Views log their entry point and writes, catch, log with context and return a clear error.
- A model change ships with its migration in the same commit; `makemigrations --check` must report no changes.
- Every change keeps `python manage.py test` green; CI (`.github/workflows/api.yml`) runs it in the built image against Postgres 17.

## 7. Deploy

`.github/workflows/api.yml`: tests on every PR and push touching `api/`. When the repository variable `CLOUD_DEPLOY` is `on`, a push to `develop` deploys to the **dev** project and `master` to **prod** (GitHub environments `dev` / `prod`, Workload Identity Federation, runtime service account `api-runtime`). Each deploy:
1. Builds and pushes the image to Artifact Registry `foodies`.
2. Runs `python manage.py migrate` as the Cloud Run job `foodies-migrate` (same image and secrets) and waits. A failed migration stops the deploy, so the old version keeps serving.
3. Deploys the Cloud Run service `foodies-api`.

Keep this file current (root `CLAUDE.md` § 4).
