# api — Developer and Agent Guide

The new backend (replatform, `docs/decisions.md` D39–D57): a Django app in one Docker image. It runs locally in `docker compose` and in production on Cloud Run (`asia-southeast1`), with PostgreSQL (local container, Neon in the cloud). **Phase 3 code complete**: data model, admin, sheet import, Google Sign-In with app tokens, the JSON API for places, dishes and collections, and adding places from Google. No photos for now (D57). In dev, sign-in and lookups answer "not configured" until the Phase 3 setup round sets their keys. The live backend is still `apps-script/` until the switch-over.

Read first: root `CLAUDE.md`, `README.md` (Local development) and `docs/decisions.md` D39–D57.

## 2. Data model (`foodies/models.py`)

Mapped from the sheet (`apps-script/src/Config.js`), English names (D51). UUID primary keys keep the sheet's App ID and Dish ID. Tables live in the `public` schema with plain names set by `db_table` (`places`, `dishes`, `place_ratings`, `place_labels`, `labels`, `people`, `master_options`, `places_usage`, `lookup_cache`, `audit_log`, `collections`, `collection_places`); Django's own tables keep their `auth_*` / `django_*` names. A new model gets a `db_table` too.

| Model | Holds | Sheet source | Notes |
|---|---|---|---|
| `Person` | The two users: name, Google email, `position` 1 or 2, `token_version` | Script Property `PEOPLE` | `position` = order of the Rating / Review columns and of `ALLOWED_EMAILS`; bumping `token_version` signs that person out everywhere |
| `MasterOption` | `kind` (rating / type / genre / category), `value`, `rank` | "Master" | Unique per kind; for ratings, higher rank = better |
| `Label` | Tag name | "Labels" cell | Unique ignoring case (`cleanLabels_` rule) |
| `Place` | All place fields, `labels` (many-to-many), Google fields, `version` | "Food List" | `id` = App ID; `version` for the edit conflict check (D24). UniqueName and Hyperlink are derived, not stored |
| `PlaceRating` | `place`, `person`, `score` (a Master rating), `review` | Rating / Review (name) columns | One per person per place |
| `Dish` | `place`, name, price, liked (''/Yes/No), best, note | "Dishes" | `id` = Dish ID; deleted with its place |
| `PlacesUsage` | `period` ("2026-11-22" or "2026-11"), `count` | Script Property `USAGE` | Places spend counter, Asia/Jakarta days |
| `LookupCache` | `place_id`, `data` (our shape of a Google result), `created_at` | Apps Script `CacheService` | Lookup results for 10 minutes, so adding one needs no second paid call (D12) |
| `AuditLog` | `at`, `person`, `action`, `entity`, `entity_id`, `changes` (JSON) | — | Every write; read-only in the admin |
| `Collection`, `CollectionPlace` | Named list of places (name, note, `version`); entries with `added_at` / `added_by` | — | D49; a place appears once per collection |

Text limits are generous in the database; the API enforces the sheet's limits (`cleanValue_`, `cleanDish_`) in Phase 3.

## 3. Endpoints

Every endpoint except health and sign-in needs `Authorization: Bearer <app token>`. Replies are JSON `{"ok": true, ...}` or `{"ok": false, "error": "<message safe to show>"}` with a 4xx/5xx status, and `Cache-Control: no-store`. Bodies are JSON. Field names are camelCase (`payload.py`).

| Method + path | Body | Reply | Rules |
|---|---|---|---|
| `GET /api/health` | — | `{"ok": true}` | No sign-in. `503` if the database is unreachable |
| `POST /api/auth/google` | `{credential}` (Google ID token) | `{token, person}` | No sign-in. Google's library checks signature, audience (`GOOGLE_CLIENT_ID`), expiry, verified email; the email must be in `ALLOWED_EMAILS` (403 otherwise). `503` until configured |
| `GET /api/auth/me` | — | `{person}` | |
| `POST /api/auth/sign-out-everywhere` | — | `{}` | Bumps `token_version`, so every token of this person stops working |
| `GET /api/bootstrap` | — | `{people, options, places, dishes, collections}` | Everything in one payload, like the Apps Script `list` |
| `POST /api/lookup` | `{input}` (pasted text with a link, or a name) | `{places: [...]}` | Up to 5 Google results. Each Places request reserves quota first: `429` past `DAILY_LIMIT` / `MONTHLY_LIMIT`. `503` until `PLACES_API_KEY` is set. Only Maps / share.google links |
| `POST /api/places` | `{placeId?, fields, ratings?}` | `{duplicate, place}` | With `placeId`: Google data from the lookup cache (one paid GetPlace if expired), never from the phone (D12); the phone's non-empty fields win; `lookupStatus: added`; an existing place with the same Google ID is returned with `duplicate: true`. Without: manual add (`lookupStatus: manual`), name required |
| `PATCH /api/places/<id>` | `{version, changes?, ratings?}` | `{place}` | `409` if `version` is not the current one (D24). Only changed fields are written; any change bumps `version` |
| `POST /api/dishes` | `{place, name, price?, liked?, best?, note?}` | `{dish, bestDish}` | |
| `PATCH` / `DELETE /api/dishes/<id>` | changed fields / — | `{dish, bestDish}` / `{bestDish}` | Last-write-wins (D25). Best Dish = starred names, joined; it does not bump the place's version |
| `POST /api/collections` | `{name, note?}` | `{collection}` | |
| `PATCH` / `DELETE /api/collections/<id>` | `{version, name?, note?}` / — | `{collection}` / `{}` | `409` on a stale version. Deleting keeps the places |
| `POST /api/collections/<id>/places` | `{placeIds: [...]}` | `{collection}` | Up to 500; already-added places are left alone; any unknown id → 404 and nothing added |
| `DELETE /api/collections/<id>/places/<placeId>` | — | `{collection}` | |
| `/api/admin/` | — | Django admin | Django superuser login. Session cookie `__session` (the only cookie Firebase Hosting forwards), CSRF token kept in the session; CSS served by WhiteNoise |

`ratings` is `{"<personId>": {"score": "<Master rating>", "review": "..."}}`. Input checks (`clean.py`) match the Apps Script: text up to 200 characters (reviews 1000), Instagram `@name` → link, Google Maps or share.google links only, labels up to 20 × 40 characters, unique ignoring case. New Type / Genre / Category values join their Master list. Every write adds an `AuditLog` row with old and new values.

## 4. Settings (environment variables)

| Variable | Required | Local (`docker-compose.yml`) | Cloud Run |
|---|---|---|---|
| `DATABASE_URL` | yes | the `db` container | Secret Manager `DATABASE_URL` (Neon pooled string, `sslmode=require`) |
| `DJANGO_SECRET_KEY` | yes | `local-dev-only` | Secret Manager `DJANGO_SECRET_KEY` |
| `DJANGO_DEBUG` | no | `1` | unset (off) |
| `DJANGO_ALLOWED_HOSTS` | no | `*` | `*` (default) |
| `PORT` | no | — (runserver on 8000) | set by Cloud Run; image default 8080 |
| `GOOGLE_CLIENT_ID` | for sign-in | unset (sign-in answers 503) | the OAuth Web client ID (not secret), setup round of Phase 3 |
| `ALLOWED_EMAILS` | for sign-in | unset | Secret Manager: the two emails, comma-separated, in Person position order |
| `PLACES_API_KEY` | for lookups | unset (lookup answers 503) | Secret Manager: a server key restricted to Places API (New) |
| `DAILY_LIMIT` / `MONTHLY_LIMIT` | no | 50 / 900 | same defaults; Places requests are refused past them |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | for admin over HTTPS | unset | the site origin, e.g. the dev `.web.app` address |

App tokens are signed with `DJANGO_SECRET_KEY` and expire after 30 days (`APP_TOKEN_MAX_AGE`); changing the key signs everyone out. `DISABLE_SERVER_SIDE_CURSORS` is on because Neon's pooler (PgBouncer, transaction mode) cannot keep server-side cursors. Static URL `/api/static/`; the image runs `collectstatic` and WhiteNoise serves the files. Time zone `Asia/Jakarta`: sheet times without a zone are read as Jakarta time. Logs go to stdout (Cloud Logging on Cloud Run). Never log tokens, keys or a user's location.

## 5. Commands (all inside Docker, from the repo root)

| Task | Command |
|---|---|
| Run API + database + web | `docker compose up` |
| Tests | `docker compose run --rm api python manage.py test` |
| After changing `models.py` | `docker compose run --rm api python manage.py makemigrations` (commit the new file), then `… migrate` |
| Check models and migrations match | `docker compose run --rm api python manage.py makemigrations --check --dry-run` |
| Admin user (local) | `docker compose run --rm api python manage.py createsuperuser` |
| Sheet import | `docker compose run --rm api python manage.py import_sheet --people "Name1,Name2" --places food-list.csv [--dishes dishes.csv] [--master master.csv] [--dry-run]` |
| Rebuild after changing `requirements.txt` | `docker compose build api`, then `docker compose up -d api` (a plain restart keeps the old image) |

**`import_sheet`** reads CSV exports (File → Download → CSV, one per tab) placed in `api/` (mounted at `/app`). Never commit them (`.gitignore` ignores every `*.csv`). It:
- Accepts the English headers and the old Indonesian ones (`OLD_HEADERS` in `apps-script/src/Setup.js`).
- Matches places by App ID and dishes by Dish ID, so a re-run updates rows.
- Skips, with a warning, rows without a valid App ID (opening the live app once assigns them) and dishes whose place was skipped.
- Ignores the sheet's Photos columns: the new app has no photos for now (D57).
- Reads only ISO dates for Added At (others keep the import time). Which format a real export uses is **Unverified**.
- Runs in one transaction; `--dry-run` rolls back. `--people` gives the two names used in the `Rating (<name>)` headers, in sheet order; names stay out of the repo.

## 6. Conventions

- Settings only from environment variables; no secret, ID or URL in code (root `CLAUDE.md` § 5).
- Every endpoint is wrapped with `@api(...)` (`auth.py`): it checks the method and the token, parses JSON and turns `ApiError` into a clear reply; unexpected errors are logged with the path and answered with a generic message.
- Writes run in `transaction.atomic()` and lock the row (`get_object(..., lock=True)`); every write calls `audit()`.
- Never trust ids or values from the phone: look rows up by UUID (`get_object`), validate with `clean.py`.
- Every Places request goes through `get_place` / `search_text` (`places.py`), which reserve quota first, outside any other transaction. No new Places method or field without updating `docs/decisions.md` and checking the price tier.
- Outgoing link fetches only through `maps_link.py`, which checks the host before every hop.
- A model change ships with its migration in the same commit; `makemigrations --check` must report no changes.
- Every change keeps `python manage.py test` green; CI (`.github/workflows/api.yml`) runs it in the built image against Postgres 17.

## 7. Deploy

`.github/workflows/api.yml`: tests on every PR and push touching `api/`. When the repository variable `CLOUD_DEPLOY` is `on`, a push to `develop` deploys to the **dev** project and `master` to **prod** (GitHub environments `dev` / `prod`, Workload Identity Federation, runtime service account `api-runtime`). Each deploy:
1. Builds and pushes the image to Artifact Registry `foodies`.
2. Runs `python manage.py migrate` as the Cloud Run job `foodies-migrate` (same image and secrets) and waits. A failed migration stops the deploy, so the old version keeps serving.
3. Deploys the Cloud Run service `foodies-api` with env vars `GOOGLE_CLIENT_ID` and `DJANGO_CSRF_TRUSTED_ORIGINS` (from the GitHub environment's variables) and secrets `DATABASE_URL`, `DJANGO_SECRET_KEY`, `ALLOWED_EMAILS`, `PLACES_API_KEY` (Secret Manager). A missing secret fails the deploy; the old version keeps serving.

Keep this file current (root `CLAUDE.md` § 4).
